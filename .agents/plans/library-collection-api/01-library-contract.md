# WP1: Library contract and shared orchestration

Prerequisite: reviewed overview and unchanged baseline, or a documented rebase review. This package may scaffold the boundary but is not complete without WP2 lifecycle behavior. Do not expose the current global cancellation collector as a temporary supported API.

## Change surfaces

New `src/lib.rs`, `src/collection.rs`, `src/error.rs`, and `src/cli.rs` under existing `src/`. Move command parsing/dispatch/rendering from `src/main.rs` into private `cli`; keep a proposed `#[doc(hidden)]` CLI entrypoint exported solely for the package binary. Document it as unsupported embedding glue. It returns an exit code; only binary main calls process::exit. Calling the collection API never invokes it. This avoids duplicate module compilation and public registration/recovery exports. Existing `src/upgrade/mod.rs` and its private modules under `src/upgrade/` remain reachable only through the CLI driver.

Existing `src/config.rs`, `src/limits.rs`, `src/archive.rs`, `Cargo.toml`, `Cargo.lock` gain the shared types/driver. Keep clap argument annotations in the CLI adapter, not public Limits. Keep internal modules private and deliberately re-export only collection types. Use stable serializable public outcomes, with safe Display/Debug for errors. No raw anyhow export or source-chain escape.

## Proposed public contract

- `CollectionRequest` owns an input-source enum, selected typed `Harness` values (Claude, Codex, Pi, OpenCode), and `Limits`. No borrowed request data survives into the worker. Empty harness selection means all four; canonical sorted/deduplicated order matches current CLI.
- `InputSource::Explicit` owns a nonempty list of validated `HostSpec` values and an absolute archive root. HostSpec contains the existing alias, SSH destination, and optional per-harness source roots. Reject duplicate aliases, invalid destinations/roots and invalid limits before contacting SSH or opening archive transactions. Never read or mutate the stored host registry in this mode.
- `InputSource::Stored` owns explicit absolute paths to the configuration directory and archive root plus optional selected alias names. Empty selection means all registered hosts. Read config.json under that directory using existing private-directory and config.lock rules; release the config lock before SSH. Do not silently ignore a caller-supplied filename. Missing/empty config, unknown host and config contention are structured request errors. Config lock/directory creation by the existing loader is permitted and documented; collection never changes registered host records.
- An opt-in proposed default-path resolver uses existing HOME/XDG rules and returns explicit paths. It never mutates environment. Direct inputs and explicitly supplied stored paths do not require this helper.
- `CollectionControl` owns a caller cancellation token and optional bounded progress sender. The API derives a child token per invocation, so dropping a call never cancels siblings or the caller's parent token. Calling parent cancel intentionally cancels its descendants. Independent tokens isolate calls.
- Proposed `collect(request, control)` is async and returns `Result<CollectionReport, CollectionError>`. It requires an existing Tokio runtime; report MissingRuntime rather than panic or create a hidden runtime. No Glurp subprocess or CLI-argument emulation.
- `CollectionReport` contains one task result for every selected host/harness in deterministic order. Results identify validated host alias and harness. Statuses: Collected, NotFound, Busy, Failed, Cancelled, NotStartedDueToCancellation. Collected includes validated artifact count for this task and the local harness archive directory. Count includes unchanged collected artifacts, excludes OpenCode inventory, and is not the cumulative stored archive total. NotFound does not claim an archive directory was created. Do not return per-artifact names or contents.
- Task errors carry fixed categories: Busy, Timeout, DestinationBinding, RecoveryRequired, LimitExceeded, InvalidRemoteStream, Transport, LocalStorage, Internal. Cancellation has its own status. Request-level categories cover invalid input/config, config busy, missing runtime, CancelledBeforePlanning and worker failure. Cancellation before configuration/selection has produced a task plan returns CancelledBeforePlanning without manufacturing unknown task identities; after a task plan exists return a complete cancellation report. Unknown internal errors map to a fixed generic category, never their raw message. Define serialization explicitly; avoid deriving sensitive request Debug.
- A normal isolated task failure or Busy does not prevent unrelated hosts from running. Report overall success only when every task is Collected or NotFound. Cancellation preserves completed tasks, marks an interrupted task Cancelled unless committed or recovery failed, and marks remaining unstarted tasks explicitly. A RecoveryRequired failure outranks cancellation and is never hidden.
- Progress events contain task identity, phase and coarse counts. Never contain remote artifact names, transcripts, stderr or unsafe error text. A caller's local archive path is returned only in the final appropriate task report; do not log it automatically.

## CLI behavior and compatibility

No backward compatibility is mandated, but retaining current command syntax, config schema, archive layout, limits and safety avoids unrelated changes. The CLI converts arguments into the same request, invokes the same collection API, and translates structured outcomes into existing-style output and exit status. NotFound is success. Failed/Busy/Cancelled/NotStarted outcomes yield nonzero. Upgrade must continue bypassing config, SSH and archive locks. Host mutation and explicit rollback remain CLI commands. Automatic transaction recovery remains part of collection safety and is not removed by collection-only scope.

## Acceptance

External integration tests import only public collection symbols. Both source modes produce identical native bytes and unchanged mtimes on a second run. Invalid requests perform no SSH calls or archive transaction creation. Direct inputs leave config bytes untouched and work without HOME. Library errors serialize and format without seeded secret strings. CLI tests still exercise the same command dispatch and existing upgrade fast path.

Dependencies: WP2 supplies safe execution before the public boundary is usable. Risks: overexposure of private core or registry mutation, fixed-filename loader ambiguity, unbounded result lists. Excluded: registration/recovery public methods, cross-repo adoption and crates.io publication.
